## 55.3 — The PATH a Mac app does not get

A macOS app started from the Dock, Finder or Spotlight inherits `launchd`'s environment: PATH is `/usr/bin:/bin:/usr/sbin:/sbin`. `code`, `zed`, `tmux`, `brew`, every nvm CLI live in directories only `~/.zprofile` and `~/.zshrc` add. A launcher that spawns `code "{path}"` from that environment says *editor not installed* on a machine where you run it ten times a day.

`platform/login_path.rs`, new: `pub fn login_path() -> String` asks `$SHELL -ilc 'printf %s "$PATH"'` once (login *and* interactive, so both rc files run), takes the last line — an rc file that prints on the way sits above it — and keeps a line only if it contains a `/`, remembers it in a `static OnceLock<String>`, and falls back to `fallback_from(PATH)` (the process PATH plus `/opt/homebrew/bin` and `/usr/local/bin`, no duplicates) if the shell cannot be asked: `recv_timeout` of five seconds on a thread that waits for the child, stdin closed so nothing can wait on it. `with_login_path(&mut Command) -> &mut Command` sets `PATH` on a child. ⛔ Not a hardcoded list — `~/.nvm/versions/node/v24.11.1/bin` is not a guess anyone can make, and a live probe found `code` at `~/.local/bin/code`, which no list carries. On Windows `resolve()` returns the process PATH and both functions are `#[cfg_attr(windows, allow(dead_code))]` — 57's rule, typed here from the start, keeps `cargo check` at 0 there. Four tests: the resolved PATH holds a shell (`sh` or `cmd.exe`), two calls agree byte for byte, the fallback adds Homebrew without duplicating it, a child sees the login PATH.

**The hand-over point is `Quiet::quiet()`** from 54. `platform/mod.rs` re-exports `login_path::{login_path, with_login_path}` (`allow(unused_imports)` on Windows) and the `#[cfg(not(windows))]` body of `quiet()` calls `with_login_path(self)`: same seam, opposite direction — on Windows the app inherits the user's environment and must hide a window; on a Mac it inherits `launchd`'s bare PATH and must be handed the user's. Done there because every spawn in the crate already calls it: a first cut wired only the launcher and the editor probe, and `gh`, `git`, `ssh` and `tmux` were still spawned with no `/opt/homebrew/bin` in reach — the GitHub rows stayed dark. `shell_line` gains `#[cfg_attr(not(windows), allow(dead_code))]` (every caller is a `cmd /c` line). The test `quiet_hands_a_child_the_login_path` spawns `/bin/sh` through `quiet()` and reads its PATH back.

> `✅PLATFORM: the login path, asked once` · `✅PLATFORM: quiet hands the path over`

## 55.5 — The Mac terminal: `{script}` pays off

`open -a Terminal <file>` opens a window that *runs* an executable file — the only way to hand Terminal.app a command. So `write_local_script` on a Mac writes `temp_dir()/devgo-{session}.command` through `write_command_file` (`chmod 755`, because Terminal refuses one that is not), whose body is **`build_tmux_script`'s output, shebang aside, unchanged** (`build_mac_script(session, path, tmux)`): same session name (26), same reconcile blocks, same `=` targets, same never-kill rule, and every test that pins the WSL script pins this body. Not a flag on `build_tmux_script`: its output is pinned byte for byte by the WSL tests, and a shared function with a Mac bool would be the drift this seam exists to prevent.

What the Mac adds is only what Terminal.app takes away. Terminal runs the file with no login PATH either, so a `MAC_PREAMBLE` puts Homebrew on PATH first (`brew shellenv` behind an `-x` guard, `/usr/local/bin` appended for an Intel Mac), and if tmux is missing the script says so in one line (`brew install tmux`), `cd`s into the project and `exec`s a login shell — psmux's courtesy from 28, in bash. The run form (20): `run_script_args` on a Mac writes `devgo-run-{session}.command` from `build_mac_run_script(path, command)`: preamble, `cd '<path>' || exit 1`, the command, then `exec "${SHELL:-bash}" -l` so the window stays open in the project — Windows Terminal's `-NoExit`, spelled in bash; a run template without `{script}` writes no file. ⚠️ The path goes through `sh_quote` (26): `~/My Projects/it's here` is one word inside single quotes and the apostrophe is the one character single quotes cannot hold; the tests use that exact path (`HOSTILE_DIR`). Six tests: the Mac script is the WSL script with a preamble, the no-tmux bail, the hostile path as one word, `{script}` substituted for a local project, the run script entering the hostile directory, no run script without the placeholder.

> `✅LAUNCHER: a .command file for terminal.app` · `✅LAUNCHER: the run form stays open`
